Chat filter: blocked terms match inside ordinary words

Ragnarok: Rebirth Global  ·  player defect report  ·  10 September 2026

Reproduce — 30 seconds in game

cucumberblockedan ordinary word
Heisenbergblockedan ordinary name
okkkblockedcontains a blocked term
okaypassescontrol

okkk being blocked while okay passes is the whole diagnosis. The filter is matching blocked terms as substrings, so a term fires anywhere it appears — including in the middle of a longer, perfectly ordinary word. cucumber is censored for three letters buried inside it.

A three-letter term sits inside hundreds of normal words. Players hit this constantly, and editing the term list cannot fix it — the problem is how terms are matched, not which terms are listed.

Fix — one condition

A blocked term shorter than 4 characters must match only as a whole word, never inside a longer one.

// where a match is currently accepted:
if (term.length < MIN_SUBSTRING_LEN && !isWholeWord(text, start, end))
    continue;  // short terms must stand alone

// isWholeWord: chars immediately before/after the match are not alphanumeric

Nothing is removed from your list. Every term keeps working. Ship it as a config value defaulting to 1 (current behaviour), set it to 4, and revert by setting it back. It is server-side only — no client build, no store review — and it covers words nobody has listed, including surnames and place names.

If changing the matcher is not an option

An allowlist gives most of the benefit with no matcher change: if a blocked term is found strictly inside a word on the allowlist, skip the block. A verified 473,532-word list of ordinary English vocabulary, place names and surnames is included (deploy/allowlist-en.txt), along with a ~20-line reference check. It is purely additive — it can only remove false positives, never block more.

Confirm the fix worked

Two included tools, no dependencies. selftest_filter.py fails the build if any string you authored is flagged by your own filter — worth putting in CI beside the localization export. lengthrule.py reports the false-positive rate on your own content for each setting of MIN_SUBSTRING_LEN, so the value can be chosen from your data.
