01 · The defect

The filter matches inside longer words

The filter blocks a message wherever the letters of a banned word appear. We confirmed this by placing the letters inside a made-up word, so that a block could only be caused by those letters and not by the ordinary word that first revealed the problem.

02 · Impact

Every market, and the game's own interface text

The block rate was measured separately against the common vocabulary of each shipped language. It is uniform — this is not an English-only problem.

Indonesian4.8%aksi, manusia, perubahan
Thai3.0%romanised interface tokens
English2.8%thanks, document, security
Portuguese2.8%acumulado, vermelho
Vietnamese2.2%anh, thanh, linh, kho

The service censors words from its own shipped localisation files. A player who types a word they can read on screen is told their speech is inappropriate.

What the player experiences

The message is not delivered and the sender sees a modal stating the speech is inappropriate. Nothing indicates which word caused it, and the offending sequence is not visible as a word — so the rule cannot be learned and cannot be avoided. Repeated blocking of ordinary words read as the game being broken rather than as moderation.

03 · Remediation

Four options. None of them blocks less.

Every option below removes false positives only — no entry is taken off the block list. They are independent and can ship in any order.

 ApproachTouchesResidual riskEffort
AShip the confirmed exception listData only Words outside the tested setHours
BAdd the rescue shimOne call site Names and slang not in a dictionary1 day
CMinimum-length boundary ruleMatcher condition Long entries still match inside longer words1–2 days
DReplace the matcherComponent swap None of this class1–2 weeks

A · Exception list — no code change

If the filter already consults an exception list, this is a data deployment. words-to-allow.txt holds the 343 confirmed words, one per line, each annotated with the rule responsible.

C · Boundary rule — best value per line

One condition addresses the cause rather than the symptoms. Long entries such as caralho behave exactly as they do today, so strength against substantial terms is untouched.

Entries shorter than five characters match only as whole words. Entries of five characters or more are unchanged.

With this rule in place, the filter still blocks a message that is only the word cu, and it stops blocking document. The filter still blocks a message that is only the word ks, and it stops blocking thanks.

Recommended rollout

1
Shadow. Evaluate the new decision alongside the current one and log where they differ, without changing what players see.
2
Check the direction of every difference. All differences must be messages the filter blocks today that would now be delivered. A message newly blocked indicates a wiring error, not a tuning question — none of these options adds blocking.
3
Enable. A and B may ship independently and in either order.

04 · Integration

Three lines at one call site

Call the shim where the existing filter has decided to block and knows the matched span. If that span sits inside ordinary vocabulary, suppress the block. Your matching logic, word list, severity rules and protocol are all unchanged.

# once, at startup
from rescue import Rescue
rescue = Rescue("allowlist-en.txt")

# inside your filter, where you were about to block:
if rescue.is_rescued(text, match_start, match_end):
    pass          # ordinary word — deliver the message
else:
    block()       # unchanged behaviour

Cost: 473,532 entries as a hash set, loaded once. Lookup is a single hash probe — not measurable against a network round trip. Why it works without knowing your list: you assert what is legitimate rather than identifying which entries are at fault, so it holds however the list changes.

The boundary rule, language-agnostic

// term matched at [start, end) in the message
func accept(term, message, start, end) {
    if (len(term) >= MIN_SUBSTRING_LEN) return true;   // 5 — unchanged

    // short term: require a word boundary on both sides
    before = (start == 0)          ? null : message[start-1];
    after  = (end == len(message)) ? null : message[end];
    return !isLetter(before) && !isLetter(after);
}

If your matcher is a compiled automaton, tag short patterns at build time and apply the boundary test only to those, so throughput is unaffected for the rest.

06 · Method & limitations

Messages were sent through the retail client into a private party channel, one at a time, and read back from chat history. Three controls govern what reached this report:

ControlWhy
We report a group of letters only after testing it inside a made-up word The filter blocks cucumber, but that does not show which part caused it
Two separate tests must both show a block Measured per-probe error rate is 1.2% (6 spurious in 491), so one reading is not a result
A message that was never sent counts as untested, not delivered All but 15 were retried to a real verdict; a false-negative audit over 250 words returned zero misses
LimitationConsequence
Rule set is a lower boundThere may be further entries the tested vocabulary did not reveal
Dictionary counts are derived8,414 is a projection; the 343 measured words are kept separately
Point-in-timeDescribes the service on 11–12 September 2026; a list edit changes it
Non-Latin locales under-coveredKorean, Chinese and Japanese were not swept; no conclusion is offered
